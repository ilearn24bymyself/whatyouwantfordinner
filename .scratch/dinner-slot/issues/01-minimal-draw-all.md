# 01: 最小可用版：一次抽完（只有單選一份）

**What to build:** 使用者在電腦上雙擊一鍵啟動檔，瀏覽器打開網頁；按首頁的「直接給答案」，畫面同時出現「吃什麼 → 去哪吃 → 點什麼」三層結果、總熱量，以及與熱量目標（500 卡）的差距。這張票只處理點法為「單選一份」的去哪吃（例如燒臘便當、沙威瑪），資料先用幾筆範例。結果落在容許範圍（400～600 卡）外時顯示超標提醒，例如「目標 500，這餐約 1000，要有覺悟」，但不阻擋。

架構已定案：純前端靜態網頁，無後端；店家資料放在一份資料檔，由 Claude 維護，程式只讀取。抽籤邏輯是唯一的測試切面：給它全部資料與熱量目標，它回傳三層結果、總熱量、差距與是否超標；畫面只負責顯示。

動手寫畫面前，依工作區規範從 UI 風格參考中挑 2～3 個適合手機使用的風格，用瀏覽器實際開啟範例讓使用者選定。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 使用者已從實際開啟的風格範例中選定一個風格
- [ ] 雙擊一鍵啟動檔即可在電腦瀏覽器打開網頁（.bat 遵守 CRLF、不直接寫中文的規範；port 不寫死）
- [ ] 範例資料至少包含 3 個吃什麼，其中至少 1 個吃什麼底下有 2 個以上的去哪吃
- [ ] 按「直接給答案」同時顯示三層結果、總熱量、熱量目標與差距
- [ ] 自動測試：每個吃什麼被抽到的機率相同，不受其底下去哪吃數量影響（固定亂數或大量抽樣驗證）
- [ ] 自動測試：去哪吃只會從抽中的吃什麼底下選出
- [ ] 自動測試：單選一份的去哪吃只給一份點什麼
- [ ] 自動測試：結果超出容許範圍時回報超標及差距（例如 1000 卡 → 超標 500）
- [ ] 手機寬度下畫面可正常閱讀與操作（瀏覽器縮成手機尺寸確認）
