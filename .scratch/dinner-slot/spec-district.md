# 規格：行政區篩選與連鎖店開關

**Status:** ready-for-agent

用詞依 `CONTEXT.md`：行政區、行政區篩選、包含連鎖店與便利商店、定位、附近、只抽附近、不受距離限制，以及既有的吃什麼、去哪吃、抽籤。接續 `spec-nearby.md`（只抽附近，已完成）。

## Problem Statement

使用者有時人不在要吃飯的地方：例如從內湖出發、要去石牌，現在就想知道石牌那邊可以吃哪幾種。目前的「只抽附近」只看使用者現在的定位，沒辦法預先指定要吃的區。另外，速食與便利商店沒有座標，不受距離限制，在離口袋名單很遠的地方（例如內湖）幾乎只剩這兩類，便利商店約佔一半的機會，使用者想要能把它們排除。

## Solution

首頁多一排可複選的**行政區**標籤（只列資料裡有店的區）。選了行政區，就只從這幾區的店抽籤，不看定位；一個都不選＝不限。選了任何行政區時，「只抽附近」不套用（開關變灰並註明原因）。另有一個「包含連鎖店與便利商店」開關，預設開，關掉就排除速食與便利商店，可與行政區、只抽附近任意搭配。篩完一家都不剩時，畫面顯示「沒有符合條件的店」，不抽籤，不再偷偷退回全部店。所有選項不記住，每次打開網頁都回到預設（不限行政區、只抽附近開、包含連鎖店開）。

## User Stories

1. 身為從內湖要去石牌的使用者，我想選「北投區」，這樣現在就能知道石牌那邊有哪些口袋名單可以吃。
2. 身為使用者，我想複選多個行政區，這樣可以同時看兩個區的店。
3. 身為使用者，我想一個行政區都不選就代表不限，這樣預設行為跟現在一樣。
4. 身為使用者，我想讓標籤只列資料裡有店的行政區，這樣不會點到沒有店的區。
5. 身為使用者，我想選了行政區後不看我的定位，這樣我人不在那裡也能篩。
6. 身為使用者，我想在選了行政區時看到「只抽附近的店」變灰並註明「已選行政區」，這樣我知道為什麼定位篩選沒作用。
7. 身為使用者，我想取消所有行政區後，「只抽附近」恢復原本的規則，這樣不用重新整理頁面。
8. 身為使用者，我想用開關排除速食與便利商店，這樣在內湖那種離口袋名單很遠的地方，不會被它們佔掉一半機會。
9. 身為使用者，我想讓這個開關預設開，這樣現有行為不變。
10. 身為使用者，我想讓連鎖店開關與行政區、只抽附近都能搭配，這樣各種組合都能用。
11. 身為使用者，我想在篩完一家店都不剩時看到「沒有符合條件的店」，這樣我知道是條件太嚴，不是程式壞了。
12. 身為使用者，我想讓提示告訴我怎麼調整（勾選連鎖店或關掉只抽附近），這樣我不用猜。
13. 身為使用者，我想讓沒有符合條件時不抽籤、也不偷偷改抽全部店，這樣我不會誤以為篩選有效。
14. 身為使用者，我想讓「換」按鈕套用同樣的篩選，這樣換上來的店仍符合條件。
15. 身為使用者，我想讓一次抽完與逐層抽都套用同樣的篩選，這樣兩種抽法規則一致。
16. 身為使用者，我想讓每次打開網頁都回到預設（不限、只抽附近開、包含連鎖店開），這樣畫面狀態永遠可預期。
17. 身為使用者，我想讓畫面只顯示「新店區」，這樣標籤簡短，手機放得下。
18. 身為開發者（也是使用者），我想讓資料檔存「新北市新店區」這種完整名稱，這樣之後有同名的區也不用改資料。
19. 身為使用者，我想新增店家時給 Maps 連結，由 Claude 推測行政區並標出把握高低、我確認，這樣維護方式簡單。
20. 身為使用者，我想讓連鎖店與便利商店沒有行政區，這樣它們只由「包含連鎖店與便利商店」開關管。
21. 身為開發者，我想讓資料檢查測試擋下有座標卻沒有行政區的店，這樣資料筆誤不會悄悄讓篩選失準。

## Implementation Decisions

- **抽籤入口增加兩個輸入。** 沿用既有的唯一抽籤入口，加入「選定的行政區」（可複選，空＝不限）與「是否包含連鎖店與便利商店」（預設是）。
- **篩選規則：**
  - 選了行政區：只有屬於選定行政區的去哪吃參加，**忽略定位**；沒有行政區的去哪吃（連鎖店、便利商店）是否參加，由「包含連鎖店與便利商店」決定。
  - 沒選行政區：照既有的「只抽附近」規則（有座標者半徑 3 公里內；沒有座標者不受距離限制）。
  - 「包含連鎖店與便利商店」關閉：不受距離限制（沒有座標）的去哪吃不參加，不論有沒有選行政區、有沒有定位。
  - 沒有任何參加者的吃什麼不參加第 1 層，其餘吃什麼等機率。
  - 篩完一個去哪吃都不剩：抽籤回傳「沒有符合條件」（取代既有「退回全部」的做法），畫面顯示「沒有符合條件的店」並附建議，不抽籤。
- **列出可選的行政區。** 抽籤模組提供一個小函式，從資料檔列出資料裡實際有店的行政區；首頁標籤用它產生。
- **資料檔：** 每個有座標的去哪吃增加行政區（縣市加區）；沒有座標的連鎖店、便利商店沒有行政區。15 家店依使用者確認的對照表：新店區 10 家（月見山沙威瑪、大掌櫃滷味、狀元香滷味、阿德古早味、吉安魷魚羹、吉安麵線臭豆腐、世昌水煎包、珍寶燒臘店、佳美食坊、鄭姑媽快餐）、中和區 5 家（邱家川味涼麵、大胖肉焿景新店、豪美自助餐 景新店、全福食堂、純檸檬泰式小吃）。
- **畫面：**
  - 行政區標籤：一排可點選取消的標籤，可複選，預設都不選。
  - 選了任何行政區時，「只抽附近」開關變灰、不可操作，旁邊註明「已選行政區」；取消所有行政區後恢復。
  - 「包含連鎖店與便利商店」勾選框預設勾選。
  - 沒有符合條件時，結果區不顯示，改顯示提示文字。
  - 所有選項不記住，每次載入回預設。
- **畫面顯示行政區只寫區名；資料存縣市加區。** 目前只有新北市的區，之後遇到不同縣市同名的區，才在畫面加縣市。
- **定位的取得流程不變。** 選了行政區時不需要取得定位（也不詢問）。

## Testing Decisions

- **好測試的標準：** 只驗外部行為——給定資料、選項與固定亂數，抽籤結果是什麼；不驗內部怎麼篩。
- **測試切面：** 沿用既有的唯一抽籤入口；列出行政區的小函式在同一個測試檔裡直接測，不另開新切面。
- **要覆蓋的行為：**
  - 選一個、多個行政區時，只抽到該區的店；不選時不限。
  - 選了行政區時忽略定位：即使定位在別處，仍抽得到選定行政區的店。
  - 「包含連鎖店」關閉時，沒有座標的店不出現；開啟時照既有規則。
  - 選了行政區且包含連鎖店時，連鎖店與便利商店也參加。
  - 篩完一個都不剩時回傳「沒有符合條件」，不報錯、不退回全部。
  - 沒有參加者的吃什麼不參加，其餘等機率。
  - 重抽（換）沿用行政區、連鎖店設定，仍一定換到不同的結果。
  - 列出行政區的函式只回傳資料裡實際有店的區，且不重複。
- **資料檢查測試（延伸既有）：** 有座標的店一定要有行政區，格式為縣市加區。
- **瀏覽器實測（畫面行為，不寫自動測試）：** 標籤選取與取消、複選、「只抽附近」變灰與恢復、連鎖店開關、沒有符合條件時的提示、不記住選項、一次抽完與逐層抽、手機寬度版面。
- **既有範例：** 沿用現有抽籤測試的固定亂數與構造資料寫法；原本「所有店都在半徑外就退回全部」的測試要改成新的「沒有符合條件」行為。

## Out of Scope

- 記住行政區與開關的選擇（使用者決定不記）。
- 選行政區以外的單位（自訂地段標籤、常用地點圓心）。
- 畫面顯示縣市名（目前只有新北市）。
- 標籤上顯示店數。
- 營業時間、公休日。
- 手機上線與 GitHub Pages 發佈（第 07 張票，維持暫緩）。
- 目前資料沒有北投區的店，要等使用者提供口袋名單；標籤只列資料裡有店的區。

## Further Notes

- 這份規格改變了 `spec-nearby.md` 的一項決定：原本「篩完什麼都不剩就退回全部」，現在改成顯示「沒有符合條件的店」。
- 使用者的主要情境是「人在別處，預先看某區有什麼可以吃」，所以行政區的優先權高於「只抽附近」。
- 在離口袋名單很遠的地方，速食與便利商店因為不受距離限制，會佔去大部分機會；「包含連鎖店與便利商店」開關就是為了讓使用者排除它們。
