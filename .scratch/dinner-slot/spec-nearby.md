# 規格：只抽附近的店（定位）

**Status:** ready-for-agent

用詞依 `CONTEXT.md`：定位、附近、只抽附近、不受距離限制，以及既有的吃什麼、去哪吃、抽籤、一次抽完、逐層抽。

## Problem Statement

使用者在回家路上、已經走到家附近時，才會打開晚餐拉霸機決定今晚吃什麼。目前資料裡有 19 家去哪吃，分散在安坑、景新、南勢角一帶，南北差約 3.5 公里。抽到離現在位置很遠的店，等於白抽一次，使用者得一直按「換」，直到抽到順路的店。

## Solution

首頁多一個「只抽附近」開關，預設開啟。使用者按下「直接給答案」或「一步一步來」時，手機取得**定位**，只讓**附近**（以定位為圓心、半徑 3 公里的直線距離以內）的去哪吃，加上**不受距離限制**的去哪吃（連鎖店品牌、便利商店）參加抽籤。附近沒有店的吃什麼不參加，其餘吃什麼仍等機率。定位失敗時顯示提示，並退回全部店都參加，跟現在的行為一致。整套流程不使用 Google Maps 服務，不需要金鑰與費用。

## User Stories

1. 身為在回家路上的使用者，我想讓程式用我當下的位置，只從附近的店抽籤，這樣抽到的一定是我走得到的店。
2. 身為使用者，我想用「半徑 3 公里」這個固定範圍，這樣我不用每次思考要設多遠。
3. 身為使用者，我想在首頁看到「只抽附近的店」開關，這樣我知道這次抽籤有沒有用位置篩選。
4. 身為使用者，我想讓開關預設是開的，這樣我在家附近打開就能直接用，不用每次先開。
5. 身為使用者，我想在需要時關掉開關，這樣我人不在家附近時（例如在公司）還是能照舊從全部的店抽籤。
6. 身為使用者，我想等到按下「直接給答案」或「一步一步來」時才被詢問定位權限，這樣一打開網頁不會就被詢問。
7. 身為使用者，我想在手機拒絕定位或抓不到位置時看到「抓不到位置」的提示，並自動改成從全部店抽籤，這樣我在路上不會卡住不能抽。
8. 身為使用者，我想讓附近沒有店的吃什麼自動不參加，這樣不會抽到一個附近根本沒有店的類別。
9. 身為使用者，我想讓剩下的吃什麼仍然等機率，這樣抽籤規則還是我原本定的那一套。
10. 身為使用者，我想讓連鎖店（麥當勞、漢堡王、摩斯漢堡）和便利商店在任何位置都抽得到，這樣我選到「速食」或「便利商店」時，可以自己依所在位置找最近的一間。
11. 身為使用者，我想讓「換」按鈕沿用這次抽籤時的位置與篩選，這樣換上來的店一樣在附近，不用重新詢問定位。
12. 身為使用者，我想讓「換」按鈕仍然一定換到不同的結果（有別的選項時），這樣篩選後的行為跟之前一致。
13. 身為使用者，我想讓逐層抽也套用同樣的附近篩選，這樣兩種抽法的結果規則完全相同，只差揭曉節奏。
14. 身為使用者，我想讓我的位置只留在手機上、不傳出、不紀錄，這樣我不用擔心隱私。
15. 身為使用者，我想讓「麵」只在附近有麵店時才參加，這樣麵不會因為資料放法而永遠出現。
16. 身為使用者，我想讓「便利商店」是獨立的一個吃什麼，這樣我選到的就是「去便利商店買茶葉蛋或微波食品」這件事本身。
17. 身為開發者（也是使用者），我想在電腦上用網址參數指定一組假座標，這樣我在本機就能測試附近篩選，不用等上手機。
18. 身為開發者，我想讓網址參數只是測試用途、畫面上沒有任何入口，這樣平常使用時不會誤觸。
19. 身為使用者，我想新增本地小店時只給 Maps 連結、連鎖店只給品牌名，這樣資料維護的方式簡單一致。
20. 身為使用者，我想讓整套功能不需要金鑰、不產生費用，這樣我可以長期使用，不用擔心帳單。

## Implementation Decisions

- **抽籤模組增加「定位」輸入。** 抽籤的唯一入口多一個可省略的定位參數（緯度、經度）。不給定位時行為與現在完全相同；給了就先依「附近」與「不受距離限制」篩選去哪吃，再抽籤。篩選與距離計算都放在抽籤模組內，畫面不重複實作。
- **篩選規則：**
  - 有座標的去哪吃：與定位的直線距離（球面兩點距離）在 3 公里以內才參加。
  - 沒有座標的去哪吃：一律參加。
  - 一個吃什麼底下沒有任何參加的去哪吃，就不參加第 1 層抽籤；其餘吃什麼等機率。
  - 篩選結果對三層都有效，包括「換」。
- **「換」沿用定位。** 重抽時使用上一次抽籤的結果與定位，不重新取得定位；「一定換到不同的結果」的既有規則在篩選後的集合內仍然成立；只有一個選項時維持原樣。
- **直線距離，半徑固定 3 公里，不可調整。**
- **資料檔增加座標。** 去哪吃可有座標（緯度、經度），沒有座標代表不受距離限制。座標來自使用者提供的 Maps 連結網址，由 Claude 讀取後寫入資料檔；連鎖店以品牌名登錄、不寫座標。
- **資料調整（落實本規格的資料變更）：**
  - 15 家有 Maps 連結的店寫入座標：月見山沙威瑪-新店安康店、大掌櫃滷味（安坑）、狀元香滷味、阿德古早味、吉安魷魚羹、吉安麵線臭豆腐、世昌水煎包、珍寶燒臘店、佳美食坊、鄭姑媽快餐、邱家川味涼麵、大胖肉焿景新店、豪美自助餐 景新店、全福食堂、純檸檬泰式小吃。
  - 「摩斯漢堡 新店安德店」改為品牌「摩斯漢堡」，不寫座標。麥當勞、漢堡王維持品牌、不寫座標。
  - 「回家路上的便利商店」從「麵」移出，獨立成一個吃什麼「便利商店」，底下放「便利商店」，不寫座標。
  - 「麵」只剩邱家川味涼麵。
- **畫面：**
  - 首頁新增「只抽附近的店」開關，預設開；不需要記住開關狀態。
  - 按下「直接給答案」或「一步一步來」時才取得定位；定位成功就把定位傳給抽籤；失敗則顯示「抓不到位置」提示並以不帶定位的方式抽籤。
  - 開關關閉時完全不要求定位。
- **測試用假座標：** 網址參數可指定一組座標，取代手機定位；僅供測試，畫面上沒有入口。
- **隱私：** 程式只在手機上使用定位，不傳送到任何伺服器、不寫入儲存空間。
- **不使用 Google Maps 任何服務：** 定位用瀏覽器內建功能，距離用座標在網頁內計算。

## Testing Decisions

- **好測試的標準：** 只驗外部行為——給定資料、定位與固定亂數，抽籤結果是什麼；不驗內部怎麼算距離。
- **測試切面：** 沿用既有唯一切面（抽籤入口），以固定亂數與構造的小資料測試。不新增切面。
- **要覆蓋的行為：**
  - 不給定位時行為與現在相同。
  - 3 公里內的店參加、3 公里外的店不參加（用接近邊界的兩家店）。
  - 沒有座標的店一律參加。
  - 附近沒有店的吃什麼不參加；其餘吃什麼仍等機率（大量抽籤後比例約相等）。
  - 「換」沿用定位：換「去哪吃」「點什麼」「吃什麼」後的結果都仍在篩選範圍內，且仍一定換到不同的結果。
  - 所有類別附近都沒有有座標的店時，仍抽得到不受距離限制的類別，不報錯。
- **瀏覽器實測（畫面行為，不寫自動測試）：** 開關預設開、定位被拒絕時的提示與退回全部店、用假座標網址參數驗證各種位置下抽得到哪些店、關閉開關時不要求定位、逐層抽與一次抽完在有無定位下都正常、手機寬度版面不跑版。
- **既有範例：** 現有 `tests/draw.test.js` 以固定亂數與構造資料測試抽籤；新測試沿用同樣寫法與輔助函式。

## Out of Scope

- 在結果旁顯示距離（使用者決定不需要，2026-11-12；第 10 張票取消）。
- 實際走路、騎車的路程距離（需要 Google 路線服務，要金鑰與費用）。
- 自動搜尋周邊有哪些店（Google Places 或 OpenStreetMap）；店仍然全部由使用者提供、Claude 寫入資料檔。
- 連鎖店分店的座標（使用者自己依所在位置去找最近一間）。
- 營業時間、公休日（資料與畫面都不處理）。
- 半徑可調整、手動指定位置的正式功能、記住開關狀態。
- 手機上線與 GitHub Pages 發佈（第 07 張票，維持暫緩，等整體在本機測好後再做）。
- 熱量配餐與可修改熱量目標（第 02、05 張票，維持暫緩）。

## Further Notes

- 手機瀏覽器要求網址是 https 才允許使用定位；本機網址（localhost）也允許。所以本機階段可用假座標測試邏輯，真實定位要等發佈到 https 網址後才能在手機上測試。
- 現有 15 家有座標的店南北約 3.5 公里、東西不到 1 公里；半徑 3 公里下，大多數位置會看到大部分店參加，此功能在使用者離開這一帶時最有感。
- 若篩選後完全沒有可抽的去哪吃（資料裡沒有不受距離限制的店、附近又沒店），退回全部去哪吃參加，避免無東西可抽；目前資料有連鎖店與便利商店，不會走到這條路。
- 「速食」「便利商店」因為都是不受距離限制，在開啟只抽附近時一定參加抽籤；之後加入的本地小店若都有座標，這兩類的相對機率會隨附近店家的類別數變化，屬於已確認的行為。
